# 苍穹外卖管理端

使用 Vue 3、TypeScript 严格模式、Vite、Element Plus、Vue Router 4、Pinia 和 Axios。目前实现登录页、公共后台布局、员工管理、分类管理、菜品管理、套餐管理和订单管理，其余管理页面显示“当前为 xx 页面”占位。页面复用旧版 Logo、菜单图标、登录背景图和订单提醒音。

## 本地运行

需要 Node.js `^22.18.0` 或 `>=24.12.0`，并启动 `sky-take-out` 后端（默认 `http://localhost:8080`）。

```sh
npm install
npm run dev
```

打开终端显示的地址。`/` 重定向到 `/dashboard`；未登录时进入 `/login`。表单不预填账号和密码，支持回车提交。

浏览器请求 `/api/employee/login`，Vite 将 `/api` 转发为后端的 `/admin`。需要连接其他后端时，在 `.env.development.local` 中设置以下内容，然后重启开发服务：

```dotenv
VITE_API_PROXY_TARGET=http://localhost:8080
```

登录成功后将 `token` 存入 Cookie（根路径、SameSite=Lax、HTTPS 下启用 Secure），有效期与当前后端一致，为两小时。刷新后从 Cookie 恢复登录状态，后续请求使用 `token` 请求头。业务错误展示后端原始提示；401 会清除会话并返回登录页。

## 后台布局

- 左侧入口依次为工作台、数据统计、订单管理、菜品管理、套餐管理、分类管理、员工管理；折叠后保留图标和悬浮提示。
- 折叠状态保存在本地，宽度以 0.28 秒切换；页面切换沿用旧版 0.5 秒淡入淡出及水平位移。
- 顶部读取店铺营业状态，支持营业中与打烊中的设置、取消及失败重试。
- 员工菜单显示登录接口返回的姓名，提供修改密码和退出登录。员工的 ID、账号、姓名保存在本地，刷新后恢复；退出或登录过期时清除。密码表单只向后端提交原密码和新密码，新密码限制为 6–20 位数字或字母。
- 进入后台后通过 `/ws/{sid}` 接收 `type: 1` 来单和 `type: 2` 催单消息，播放对应提示音，并显示可点击的右上角通知。点击后进入 `/order?orderId=...`。HTTPS 页面使用 `wss`，连接断开后自动重连，退出后台时关闭连接、通知和提示音。

开发服务将 `/ws` 代理到 `VITE_API_PROXY_TARGET` 对应的同一个后端。提示音能否自动播放取决于浏览器的媒体播放权限，文字通知仍可查看和点击。

## 员工管理

- `/employee` 支持按姓名查询、回车查询和清空查询；每页默认 10 条，可选 20、30、40 条，支持页码和跳页。查询及调整每页条数时回到第一页，时间显示到分钟。
- `/employee/add` 新增员工，`/employee/add?id=员工ID` 修改资料并回显；保存后返回列表，新增时可选择保存并继续添加。
- 账号为 3–20 位小写字母或数字；手机号匹配 `^1[3-9]\d{9}$`，支持 19 开头；身份证为 15 位数字，或 18 位且末位允许 `X/x`。性别传给后端时，男为 `"1"`，女为 `"0"`。初始密码及启用状态由后端设置。
- 管理员（账号 `admin`）不可修改或切换状态，当前登录员工不可禁用自己；其他员工支持确认后禁用/启用。修改本人姓名和账号后同步更新会话资料。
- 列表和详情读取失败可重试；保存失败保留输入并展示后端报错，保存过程中阻止重复提交。

## 分类管理

- `/category` 支持分类名称和菜品/套餐类型的组合查询、回车查询、清空筛选；分页与员工管理共用组件，默认 10 条，可选 20、30、40 条。
- 新增菜品分类、新增套餐分类及修改共用弹窗，标题标明操作和分类类型。修改直接回显分页接口返回的资料，保留原类型。新增可保存并继续添加，新分类按后端规则默认为禁用。
- 沿用旧版校验：名称为 2–20 位中文或英文字母，排序为 0–99 的整数。保存失败保留输入，提交期间阻止重复保存和关闭弹窗。
- 删除和启停用均需确认；关联菜品或套餐不能删除时展示后端原始原因。删除末页最后一条记录后自动回到有效页码。

## 菜品与套餐管理

- `/dish` 和 `/setmeal` 支持名称、分类和售卖状态的组合查询、批量勾选删除、修改与起售/停售，分页与员工管理共用组件。删除和状态变更需确认；起售中或菜品关联套餐等限制展示后端原始报错。
- `/dish/add` 和 `/setmeal/add` 为新增页，添加 `?id=商品ID` 回显并修改；新增默认停售，可保存并继续添加。名称沿用 2–20 位中文、英文字母或数字校验；价格大于零、最多六位整数和两位小数，按元提交；描述最多 200 字。
- 菜品口味沿用甜味、温度、忌口、辣度及原有选项，可增删口味和选项，相同类型不会重复添加；口味值以 JSON 字符串提交。
- 图片通过 `/common/upload` 的 multipart `file` 字段上传，支持 PNG/JPEG/JPG，文件大小最多 1MB（1,048,576 字节），与后端限制保持一致；上传后显示后端 URL，悬浮可删除或重新上传，失败保留原图。200×200 或 300×300 为建议尺寸。
- 套餐添加菜品弹窗按启用的菜品分类调用 `/dish/list?categoryId=...`，仅展示后端返回的在售菜品；支持跨分类选择、取消撤销本次选择及右侧移除。已选表格保留原份数，新选默认 1 份，可输入或增减至 1–99 份；套餐至少包含一个菜品。
- 分类下拉调用 `/category/list?type=1或2`；详情、分页、保存、删除及状态调用 `/dish`、`/setmeal` 对应后端接口。编辑时保留原售卖状态。保存或上传期间阻止重复操作及离开页面。

## 订单管理

- `/order` 支持全部订单、待接单、待派送、派送中、已完成和已取消六种列表，各状态显示对应列；前三种待处理状态的红色角标从 `/order/statistics` 读取，超过 99 显示 `99+`，为 0 时隐藏。
- 支持订单号、手机号和下单日期组合查询；日期范围按开始日 `00:00:00` 到结束日 `23:59:59` 提交。分页默认 10 条，可选 20/30/40 条，支持跳页；查询和切换状态时回到第一页。`?status=2/3/4/5/6` 可直接进入对应状态。
- 接单、派送、完成分别仅用于状态 2、3、4；待接单支持拒单，待付款支持取消。列表保留旧版待派送、派送中的取消入口，提交后以后台响应为准；当前后端拒绝取消已接单的订单时，显示原始报错并保留原因选择与订单状态。已完成、已取消仅查看。
- 拒单与取消复用原因弹窗，保留原版原因选项及最多 20 字的自定义原因。失败保留选择和原始后端提示，提交期间禁用重复操作与离开页面。
- 详情读取 `/order/details/{id}`，展示当前真实状态、收货人、电话、地址、送达时间、备注或取消原因、菜品及份数、支付渠道和状态、费用及支付时间。订单明细金额为单价乘份数；固定配送费 6 元与当前后端一致，打包费和总金额使用后端返回值。
- 待接单详情保留“处理完自动跳转下一条”，默认勾选；操作后刷新列表和角标。收到顶部 WebSocket 来单/催单消息时刷新数据，点击通知直接打开 `/order?orderId=...` 对应订单详情，页面内连续通知也可切换订单。
- 列表、详情与统计分别提供失败重试；状态变更后若当前页不再有效，自动回到有效页码。

## 工作台

- `/dashboard` 展示今日数据、今日订单概览、菜品总览、套餐总览和待处理订单信息五个板块。今日营业额、有效订单、完成率、客单价及新增用户均使用 `/workspace/businessData` 的汇总值，金额显示两位小数，完成率沿用旧版取整百分比。
- `/workspace/overviewOrders` 仅统计今日订单；下方列表与红色角标分别使用 `/order/conditionSearch` 和 `/order/statistics`，包含全部日期的待接单和待派送订单，保留原版两种统计范围。
- 详细数据、订单明细、商品管理与新增入口跳转到现有页面，今日订单数量可跳转到对应状态。菜品与套餐启售、停售数量分别读取当前后端的 `/workspace/overviewDishes` 和 `/workspace/overviewSetmeals`。
- 工作台和订单管理共用 `OrderListPanel`，支持分页、详情、接单、拒单、派送、原因校验、后端报错及详情处理后自动打开下一条；工作台内切换列表保留 `/dashboard` 地址。操作成功及收到来单/催单消息后刷新今日数据、今日订单、列表和角标。
- 各概览独立加载和失败重试，空数据按后端返回值显示，刷新后重新读取。工作台与统计页共用异步请求状态逻辑，忽略过期响应并在离开页面后停止更新状态。

## 数据统计

- `/statistics` 使用 ECharts 展示两行两列图表：营业额、用户、订单折线图及销量 TOP10 横向柱状图，支持悬浮查看数据；图表随窗口及菜单折叠自动调整尺寸。
- 默认近 7 日，昨日及近 7/30 日均截至昨日；本周为周一至周日，本月为月初至月末，与旧版完整周期规则一致，并修正周日的本周日期计算。四项统计统一传递 `begin/end`，日期格式为 `YYYY-MM-DD`。
- 订单总数、有效订单与完成率使用后端汇总值；后端在无订单时返回完成率 1，页面显示 `100.0%`。销量空结果显示空状态，统计失败可分别重试，快速切换时间时忽略旧响应。
- 数据导出保留近 30 天确认提示；当前 `/report/export` 不接受筛选日期，固定生成截至昨日的近 30 天运营数据。携带登录凭证读取二进制，下载为 `运营数据统计报表.xlsx`，导出期间阻止重复请求；JSON 错误显示原始原因，不下载错误文件。

## 验证

```sh
npm run test:unit -- --run
npm run build
npm run lint
npx playwright install chromium
npm run test:e2e -- --project=chromium
```

单元和组件测试覆盖接口数据、统计日期边界、二进制下载及错误解析、会话与路由守卫、密码弹窗及消息连接的清理和重连。浏览器测试覆盖登录、公共布局、员工、分类、菜品和套餐的查询分页、新增/修改及校验、状态确认、批量删除、口味、图片上传、套餐选菜与份数、订单六种状态与详情、原因填写、处理流程、通知联动、操作限制和失败重试，以及统计图表、时间切换、独立重试、空销量与报表下载。默认测试模拟后端接口和 WebSocket。

如需使用本机安装的 Chrome，可设置 `PLAYWRIGHT_CHROMIUM_CHANNEL=chrome`。

连接真实后端的浏览器测试需要额外提供账号和密码：

```sh
E2E_ADMIN_USERNAME=你的账号 E2E_ADMIN_PASSWORD=你的密码 npm run test:e2e -- --project=chromium
```

未设置这两个环境变量时，真实后端测试会跳过。真实测试只执行登录、营业状态、工作台概览、各管理列表、商品和订单详情读取、统计查询、报表下载及刷新；新增/修改、上传、删除、启停用、密码修改、营业状态保存和订单处理使用模拟接口测试。

## 构建部署

`npm run build` 输出到 `dist/`。部署服务器需将 `/api/*` 代理到后端 `/admin/*`，将 `/ws/*` 代理到同一后端并支持 WebSocket Upgrade，同时将前端路由回退到 `index.html`，以支持直接访问和刷新管理页面。
